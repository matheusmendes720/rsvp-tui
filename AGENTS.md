# RSVP-TUI — AGENTS.md

This is a hybrid **Rust + Python** workspace for an RSVP (Rapid Serial Visual
Presentation) speed-reading TUI. Read this before touching anything; the layers
have non-obvious wiring that wastes time to rediscover.

The GitNexus MCP tooling rules live in **`CLAUDE.md`** (same dir).
Full architecture, subcommand reference, and feature list live in **`README.md`**.
Spec sheets (`docs/SPEC.*.md`) cover algorithms, data model, design.

---

## Layer model (not obvious from filenames)

```
┌────────────────────────┐    ┌─────────────────────────┐    ┌─────────────────────────┐
│ rsvp-cli/   (Rust CLI) │    │ rsvp-tui/ (Python TUI)  │    │ rsvp-core/ (Rust ext)   │
│  clap + ratatui        │    │  Textual + Click +      │    │  pyo3 extension         │
│  native reader,        │ ←→ │  Pydantic v2            │ ←→ │  tokenize, ORP, parse   │
│  doctor/themes/etc     │    │  screens + figures      │    │  53 exports             │
└────────────────────────┘    └─────────────────────────┘    └─────────────────────────┘
```

* **`rsvp-cli`** is a *separate* compiled binary, not a Python wrapper. It calls
  into Python only for TUI subcommands; pure-Rust subcommands (`doctor`,
  `themes`, `where`, `version`, `version --json`) never spawn Python.
* **`rsvp-core`** is **never** a hard dependency. `rsvp_tui/__init__.py` does
  `try: import rsvp_core` and falls back to pure Python in `fallbacks.py`.
  Until you `uv run rsvp-build`, you're in fallback mode (slower tokenization,
  no EPUB parse).
* **`rsvp_workspace/`** is a tiny shim package — its `__init__.py` re-exports
  `main()` from `scripts/*.py` so they can be wired as console scripts in the
  root `pyproject.toml`. Don't add logic here.

## Quick start (with uv)

```bash
uv sync                      # installs everything into .venv
uv run rsvp-build            # one-time ~30s — builds rsvp-core + rsvp-cli
uv run rsvp-test             # 179 pytest tests (rsvp-tui/tests/)
uv run rsvp                  # == uv run rsvp-tui (default: legacy UI)
RSVP_NEW_UI=1 uv run rsvp    # opt into the screens-based UI
```

Without uv: `make <target>` or `bin/rsvp-task <name>` / `bin/rsvp-task.bat`.

## Canonical task surface

All 20+ entry points are real console scripts (root `pyproject.toml`,
`[project.scripts]`). The full table is regenerated by `uv run rsvp-tasks`. The
ones you'll actually use:

| Task | What it does |
|---|---|
| `uv run rsvp-tui` | Launch interactive TUI (`python -m rsvp_tui.cli`) |
| `uv run rsvp-cli` | Launch native Rust CLI |
| `uv run rsvp-read <file>` | Open a book in the TUI |
| `uv run rsvp-import <file>` | Add a book to the library |
| `uv run rsvp-library` | Browse/manage the library |
| `uv run rsvp-config` | Live settings modal |
| `uv run rsvp-palette` | Fuzzy command palette |
| `uv run rsvp-demo` | Dependency-free demo (no rust build needed) |
| `uv run rsvp-build` | Build Rust core + Rust CLI (one-shot) |
| `uv run rsvp-dev` | Editable install (`maturin develop --release`) |
| `uv run rsvp-sync --rebuild` | Sync + force-rebuild the Rust ext |
| `uv run rsvp-clean` | Remove `build/`, `dist/`, `__pycache__`, caches |
| `uv run rsvp-test` | Full pytest run |
| `uv run rsvp-lint` / `rsvp-format` / `rsvp-typecheck` / `rsvp-verify` | Quality gates |

Implementation lives in `scripts/<name>.py`; `scripts/tasks.py` is the source of
truth for the table text.

## Key env vars

| Var | Effect | Source of truth |
|---|---|---|
| `RSVP_HOME` | Override `~/.rsvp` data dir | `rsvp_tui/cli.py` |
| `RSVP_NEW_UI` | Force-enable screens-based UI (default: legacy single-screen) | `rsvp_tui/app.py` |
| `RUST_LOG` | rsvp-cli log level (`error`/`warn`/`info`/`debug`/`trace`) | rsvp-cli Rust code |
| `NO_COLOR` | Disable ANSI in helper scripts | scripts/* |
| `PYTHONIOENCODING=utf-8` | Needed for non-ASCII books on Windows | General |

Default data locations: `~/.rsvp/{config.json, library.db, notes/, cache/}`.

## Adding features (the three relevant paths)

**1. Rust function (tokenization, parsing, perf-critical):**
* Add to the appropriate `rsvp-core/src/*.rs` module.
* Expose via `lib.rs` (`#[pyfunction]` or `#[pyclass]`).
* Add a matching `rsvp_tui/fallbacks.py` entry so the function works **without**
  the Rust build.
* Re-export the new symbol from `rsvp_tui/__init__.py`'s `try/except` block.

**2. New screen or modal (`screens/`):**
* Subclass `ScreenBase` (or `ModalScreen`); `base.py` has the boilerplate and
  defines the `FigureState` singleton.
* Cross-cutting changes go through `screens/messages.py` message classes
  (`BookOpened`, `ConfigChanged`, `FigureChanged`, …) — don't poke the app
  directly.

**3. New figure (word-display strategy):**
1. Subclass `Figure` in `rsvp_tui/figures/your_figure.py` — implement
   `render(state: FigureState) -> RenderableType`.
2. Register it in `rsvp_tui/figures/registry.py`.
3. Add a test in `rsvp-tui/tests/test_figures.py` (the registry wires the
   picker modal and `cycle_figure` automatically).

If you must touch legacy `widgets/`, keep a PEP 562 lazy `__getattr__` re-export
at the legacy path so the deprecation warning only fires on actual use.

## Conventions / pitfalls (the gotchas)

* **Rust core is optional.** Always make new Rust exports work via
  `rsvp_tui/fallbacks.py`. An agent that adds a Rust function without a fallback
  breaks `uv run rsvp-demo` and CI without `rsvp-build`.
* **mypy excludes `rsvp-tui/build/`.** A stale setuptools-rust artefact from
  the first install attempt; never put source there. (Root `pyproject.toml`,
  `[tool.mypy].exclude`.)
* **mypy is strict + `ignore_missing_imports`.** New code must type-check.
* **Two `py.typed` packages**: `rsvp-tui/py.typed` is the PEP 561 marker; the
  rsvp-core extension ships its own types from Rust via pyo3.
* **Pytest warnings are honest, not noise.** The deprecation warnings from the
  legacy `widgets/` shims are intentionally visible — they go silent once
  `RSVP_NEW_UI=1`. Don't add `filterwarnings = ignore` (see root
  `pyproject.toml`, comment block above `addopts`).
* **Code style lives in `pyproject.toml`** (root + `rsvp-tui/`): `ruff` rules
  `E,F,I,N,W,UP,B,C4,SIM`; `black` line-length 100; `mypy --strict`. Do not
  duplicate style rules in code.
* **Tests are in `rsvp-tui/tests/`**, not root. `pytest` is configured via the
  root `[tool.pytest.ini_options].testpaths`.
* **`app.py` routes between legacy and new UI** via `RSVP_NEW_UI`. If you
  change init/teardown, both paths must keep working.
* **`config.json` has schema_version 2.** `ConfigManager.load()` migrates v1
  on read; don't break that path.
* **Console-script wiring is non-trivial.** The root `[project.scripts]`
  invokes functions named in `rsvp_workspace/__init__.py`, which re-export
  `main` from `scripts/<name>.py`. To add a new `rsvp-foo`: add to root
  `pyproject.toml`, add a `foo` symbol in `rsvp_workspace`, add a
  `scripts/foo.py:main`, add the row to `scripts/tasks.py`.

## Common fixes

| Symptom | Fix |
|---|---|
| `ImportError: rsvp_core` | `uv run rsvp-build` (or run with fallback intentionally) |
| Modern terminal — display glitches | `TERM=xterm-256color` (Windows Terminal defaults work) |
| Unicode errors on Windows | `chcp 65001` or set `PYTHONIOENCODING=utf-8` |
| Stale Rust build / mypy double-import errors | `uv run rsvp-clean` then `uv run rsvp-build` |
| `rsvp-cli` not found | `uv run rsvp-build` builds the Rust binary; otherwise `uv run rsvp-tui` covers it |
